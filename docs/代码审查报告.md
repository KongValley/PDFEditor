## 逐条详情

### R1 合并时批注 id 冲突 → 被并页批注在保存后消失(HIGH)

**现象**:把「自己文档的副本」(提取/导出/另存产物)合并回原文档后,被并页上的批注在保存后从输出文件里消失。

**触发路径**:文档 A 有批注 X → 用提取/导出/另存得到含 X(同一 id)的 B → 打开 A → 合并 B → 保存。

**证据**(探针 `tmp/review/r1.js` + `tmp/review/r1-check.mjs`,实测输出):

| 文件 | 自产批注总数 | 分布 |
|---|---|---|
| `sample-zh-1.pdf`(A 原件) | 1 | page0=1(id `1a5c2b2a-…`) |
| `sample-zh-1-1.pdf`(B = A 第 1 页副本) | 1 | page0=1(同一 id) |
| `out.pdf`(A 合并 B 并保存,4 页) | 1 | page0=1,page1=0,page2=0,page3=0 |

合并后模型 `modelAfterMerge = [{id: 1a5c2b2a…, page: 0}]`(仍只有 1 条)→ 证明导入阶段按 id 去重跳过了副本里的同 id 批注;
随后保存执行 `replaceOwnAnnotations`(先剥离全部 `/PdEditorData` 再按模型重建),被并页的批注因此被清除。

**影响面**:用户可见的数据丢失,且输出文件已落盘。撤销可回退模型,但不能恢复已写出的文件。

**建议改法**:`importAnnotations` 判重键从 `id` 改为 `id + page`;同 id、不同页时用 `crypto.randomUUID()` 重新发号后再导入;
同 id 同页仍视为重复跳过。`extractEditorAnnotations` 保持原样(提取时保留原 id)。

### R12 便签文本含非 ASCII 时批注对象损坏(HIGH,修复回归测试时发现)

**现象**:便签(以及任何把用户文本写进 `/Contents` 的批注)在保存后的 PDF 里对象损坏;
重开文档时该批注丢失,pdf.js 报 `Warning: _parsedAnnotations: "FormatError: Illegal character: 41"`,
pdf-lib 报 `Trying to parse invalid object` / `Invalid object ref: 18 0 R`。

**成因**:`buildAnnotDict` 用 `PDFString.of(ann.text)` 写 `/Contents`。`PDFString.of` **不做转义**,
按字符低位字节直接写入字面量字符串:中文码位低位为 `)`(如 `缩` = U+7F29 → 0x29)或 `\` 时会提前结束/转义,
整个批注字典随之无法解析。

**证据**(探针:新建便签 → 保存 → 重开):

- 修复前:`beforeSave = [{kind:"note"}]` → 重开后 `after = []`(批注丢失);对象 `18 0 R` 无法解析;
- 修复后:`after = [{kind:"note", page:0}]`;`/Contents` = `<FEFF7F29756556FE68C067E5>`(UTF-16BE + BOM,可正确解码「缩略图检查」)。
- 说明:审查基线里 step8 的便签文本恰好不含 `)`/`\` 低位字节,因此旧冒烟未能发现。

**影响面**:保存即损坏 —— 受影响批注在重开时消失(数据丢失);已保存的历史文件同样读不回该批注。

**建议改法(已实施)**:`Contents` 改用 `PDFHexString.fromText(text)`;`/NM` 同步改为 hex 写入,避免同类风险。

### R5 缩略图仍由 pdf.js 绘制批注,与主视图不一致(MEDIUM)

**现象**:缩略图显示的是「文件里已保存的批注」,与主视图(批注只由 SVG 覆盖层绘制)不一致;
删除/新增未保存的批注时缩略图不更新。

**触发路径**:打开含已保存批注的 PDF(缩略图由 pdf.js 画 `/Annots`);在模型里删除该批注(不重载、不保存)→ 缩略图不变。

**证据**(探针 `tmp/review/r5.js`,打开 `tmp/e2e-baked.pdf`):

- 删除前:`[data-thumb="1"] canvas`(84×118)扫描到 **11 个黄色像素**;
- 删除模型全部注释后:`annState.items.length = 0`、主视图覆盖层便签元素 `overlayNoteCount = 0`,同一缩略图仍为 **11 个黄色像素**;
- 代码对照:`PageThumb.vue:45` 的 `page.render({canvasContext, viewport})` 未传 `annotationMode`,
  而主视图 `PageCanvas.vue:83-89` 已传 `pdfjs.AnnotationMode.DISABLE`。

**影响面**:视觉不一致与误导(缩略图显示已被删除的批注);未保存的新批注在缩略图中不可见。

**建议改法**:`PageThumb.renderThumb` 增加 `annotationMode: pdfjs.AnnotationMode.DISABLE`,让批注单一来源=覆盖层;
若希望缩略图显示批注,则应改为叠加模型(需另做,不在本次范围)。

### R6 导出/提取/拆分/合并未提交画布编辑器内容(MEDIUM)

**现象**:在文字注释的画布编辑器里输入但未失焦(Esc/回车/Ctrl+Enter 才提交),直接导出/提取/拆分/合并,输出缺少最后一次编辑。

**触发路径**:双击文字注释 → 改文本 → 不失焦 → Ctrl+E 或「提取/导出/拆分/合并」。

**证据**(探针 `tmp/review/r6.js`):

- 编辑器打开中 `editorStillOpen = true`;导出前模型文本 `beforeExportModel = "旧文本"`;
- 导出产物读回 `exportedTexts = ["旧文本"]`(期望 `"新文本未提交"`)。

**代码路径**:`saveTo` 会先调 `commitOpenEditor()`(`actions.ts:99`),但下列入口没有:
`exportCurrentPageImage`(:137)、`exportPages`(:345)、`extractPages`(:374)、`splitPdfs`(:407)、`exportPagesAsImages`(:466)、
`mergePdfs` 的输出与撤销快照(`:266` 及 `annotationsBefore`)。

**影响面**:导出/拆分/合并的文件内容与屏幕不一致;合并的撤销快照也会漏掉这段编辑。

**建议改法**:上述入口在取 `exportAnnotations()` 之前统一调用 `commitOpenEditor()`(该函数已在 `store/ui.ts` 导出)。

### R7 页面撤销失败时条目回压,与主进程快照栈错位(MEDIUM)

**现象**:`undoSinglePage` 的 `catch` 无条件把条目压回撤销栈;当失败发生在主进程快照已成功弹出之后
(即 `await reloadDocument(result.buffer)` 抛错),条目回压会让下一次 Ctrl+Z 再弹出一份更早的快照,跨越一次操作。

**证据**(代码路径,`src/renderer/src/store/annotations.ts:245-272`):

```
251  try {
252    const result = await window.pdfAPI.invoke('pageops:undo', docId)   // ← 已消费主进程快照
260    await reloadDocument(result.buffer)                                // ← 此处抛错即错位
267    redoStack.push(entry)
268  } catch (err) {
269    undoStack.push(entry)                                             // ← 无条件回压
```

**影响面**:状态错位(多回退一步)、注释现场与主进程 buffer 不再对应。触发需要渲染层故障,未能自然复现,故以代码路径为证据。

**建议改法**:拆成两段——IPC 返回 `!ok`/缺 buffer 时回压;IPC 成功之后的任何失败只 toast
「撤销完成但界面刷新失败,请重开文档」,不回压(此时两端栈已一致前进)。

### R10 提取/导出/拆分/合并表单文档丢失表单字段(MEDIUM)

**现象**:对表单 PDF 做提取/导出/拆分/合并后,产物没有 `/AcroForm` 字段定义,只有孤立的 `/Widget` 批注;
填写后保存无法写回表单值(只得到「表单字段未找到」告警)。

**证据**(探针 `tmp/review/s3.js`、`tmp/review/f1.js` + `tmp/review/s3-acroform.mjs` / `s3-check.mjs`):

| 文件 | 页 | 页面 `/Annots` | `/AcroForm` | `getForm().getFields()` |
|---|---|---|---|---|
| `samples/sample-form.pdf`(原样) | 1 | `/Widget` ×2 | 存在(Fields=2) | 2(`name`、`agree`) |
| `form-in.pdf`(导出·勾选包含注释) | 1 | `/Widget` ×2 | **NONE** | 0 |
| `form-out.pdf`(导出·不勾) | 1 | 无 | NONE | 0 |
| `merged.pdf`(把 sample-form 合并进来) | 2 | — | **NONE** | — |

合并探针另测:合并后渲染层 `docState.formFields.length = 0`(表单字段列表未随合并刷新)。

**成因**:所有导出/拆分路径都用 `PDFDocument.create()` + `copyPages`(`docops.ts:86`、`:202`),
append 路径把页面复制进目标文档(`docops.ts:70-81`)——**页面级复制不会带上文档级 `/AcroForm`**。

**影响面**:表单文档的副本/合并件里控件成为孤儿:主视图能画出控件(Widget)但保存时写不回,表单值静默丢失(仅控制台与汇总提示)。

**建议改法**:复制页面后按需复制源文档 `/AcroForm`(pdf-lib 可读 `doc.catalog` 的 AcroForm 字典并注册到目标 catalog),
或在含表单字段时对用户给出显式提示。不勾「包含注释」时把 Widget 一并剥离属既定语义(D5),此处仅提示。

### R3 加密文档另存后主进程 entry.path 未更新(LOW)

**证据**(代码路径):`src/main/ipc.ts` 明文分支在 `:262` 执行 `entry.path = targetPath`,
而 encrypted 分支在 `:245-250` 直接 `return { ok: true, mode: 'sidecar', savedPath: targetPath }`,不更新 `entry.path`。
`pageops:export` 的保存对话框默认目录取自 `dirname(entry.path)`(`:177`)。

**影响面**:加密文档另存到新目录后,后续导出/提取对话框的默认目录仍指旧位置(功能可用,易误存)。

**建议改法**:encrypted 分支 return 前加 `entry.path = targetPath`。

### R4 全部页码越界时写出无用 PDF 并报成功(LOW)

**证据**(探针 `tmp/review/r4.js`):`exportPages([99], …/empty.pdf)` 之后

- renderer toast:`{"text":"已导出:…\\empty.pdf","kind":"info"}`;
- 产物实测:`pages: 1, size: 869 B`(pdf-lib 读回 1 页空白)。

**触发**:直接 IPC `pageops:apply {kind:'export', pages:[99]}`;UI 经 `parsePageRange` 校验,正常不可达。

**影响面**:边界健壮性:写出无意义文件并报告成功。

**建议改法**:`docops.ts` export 分支在 `indices.length === 0` 时返回 `{ ok:false, error:'未指定要导出的页面' }`。

### R8 sidecar 校验过严,连带丢弃 formValues(LOW)

**证据**(探针 `tmp/review/r8.js`,sidecar 仅含 `{"version":1,"formValues":{"probe":"hit"}}`):
`sidecarIsNull = true`、`formValues = {}`(期望 `probe: "hit"`)。

**成因**:`src/main/lib/pdfio.ts:60` 的 `if (!Array.isArray(data.annotations)) return null`。

**影响面**:外部工具写出的 sidecar(无 annotations)会让表单值一并失效。

**建议改法**:`annotations` 缺失时按 `[]` 处理;仅在存在但类型不对时 `console.warn`。

### R9 画笔观感与覆盖层差异(LOW,Adobe 端存疑)

**证据**:

- `tmp/e2e-baked.pdf` 中高亮批注的 `/CA = 0.4`,其外观流内含 `ExtGState { /ca 0.4, /BM /Multiply }`(pdf-lib 读出);
- 同一高亮在 **pdf.js 原生批注绘制** 与 **本应用画笔** 下采样完全一致:`[255,243,194]` 对 `[255,243,194]`(底图 `[255,255,255]`,探针 `tmp/review/r9.js`);
- 便签折角在 `canvasannot.ts` 中叠加了 `globalAlpha = ann.opacity`,SVG 覆盖层无该透明度。

**影响面**:观感级差异;`/CA` 与外观流内 alpha 是否在 Adobe 侧双重减淡未实测 → 见「存疑」。

**建议改法**:如后续收到观感反馈,去掉 AP 内的透明度叠加以便与 `/CA` 单一来源一致。

### R11 保存部分成功却返回失败(LOW,未运行时复现)

**证据**(代码路径,`src/main/ipc.ts:258-264`):`rename(tmpPath, targetPath)` 成功之后才 `rename(tmpSidecar, sidecarPath)`;
sidecar 替换失败会进入 `catch` → 清理临时文件 → `throw` → 渲染层收到「保存失败」,但 PDF 文件其实已更新。

**影响面**:用户误以为未保存,可能重复操作;无数据损坏。

**建议改法**:sidecar 写入失败降级为 `warnings` 条目,主文件成功即返回 `ok: true`。
